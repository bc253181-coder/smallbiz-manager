# 13 · 手机安装（PWA）· 设计

> 阶段 17。不需要额外的账号或费用。

## 1. 要解决的问题

- 店主和店员主要用手机，现在每次都要打开浏览器、找书签，地址栏占地方，用起来不像 App
- 网络不好时（市场、仓库里信号差）页面打不开，只看到浏览器的报错页

## 2. 功能

| # | 功能 | 说明 |
|---|---|---|
| P1 | **添加到主屏幕** | 安卓 Chrome / Edge 显示「安装 App」；iPhone Safari 通过「分享 → 添加到主屏幕」。安装后有独立图标、全屏打开、没有地址栏，启动时显示品牌色的启动画面 |
| P2 | **安装引导** | 手机上第一次登录后，在页面顶部提示一次「把 SmallBiz 添加到主屏幕」（安卓一键安装；iPhone 显示两步图示）；关掉后 30 天内不再提示；设置页也有入口 |
| P3 | **打开更快** | 页面程序文件缓存在手机上，第二次打开不用重新下载，弱网下也能秒开 |
| P4 | **断网提示** | 没有网络时页面照常打开，顶部显示「网络已断开，恢复后会自动刷新数据」，开单、保存等按钮提示需要联网，不会丢失已填写的内容；恢复网络后自动重新加载数据 |
| P5 | **新版本提示** | 发布新版本后，已打开的 App 显示「有新版本，点击更新」，不会一直用旧版本 |
| P6 | 图标与外观 | 192 / 512 像素图标（含安卓自适应图标）、iPhone 图标、状态栏颜色与品牌一致；中英文名称跟随界面语言 |

## 3. 数据安全（重要）

- **不在手机上缓存任何经营数据**（商品、价格、客户、订单等接口数据一律不缓存），只缓存页面程序文件和图标。原因：多人共用手机、退出登录、切换店铺时不会残留别家店的数据；也不会看到过期的库存和价格
- 因此本阶段**不做离线开单**（离线开单需要处理库存冲突、单号冲突，复杂度高，放到以后单独评估）

## 4. 技术方案

- `vite-plugin-pwa`（Workbox）生成 Service Worker 和 manifest；只预缓存构建产物（JS、CSS、字体、图标），`/api/*` 不经过缓存
- 更新策略：新版本下载完成后提示用户刷新（不自动刷新，避免打断正在开的单）
- 图标：用现有的品牌图形生成 PNG（192、512、可裁剪的 maskable 512、180 的 apple-touch-icon）
- Nginx：`sw.js`、`manifest.webmanifest` 设为不缓存，保证能及时拿到新版本；其余带哈希的静态文件仍长期缓存
- PWA 需要 HTTPS（正式部署已有）；本地开发 `localhost` 也可以

## 5. 测试计划

- 构建产物里有 manifest、Service Worker、全部尺寸的图标；manifest 字段正确（名称、颜色、`display: standalone`、start_url）
- 端到端：页面注册了 Service Worker；断网（浏览器离线模式）后刷新页面仍能打开并显示断网提示；恢复网络后提示消失、数据重新加载；接口请求不会被缓存（断网时接口请求失败而不是返回旧数据）
- 安装提示：手机宽度下第一次显示，关闭后不再显示
- Lighthouse 的 PWA 可安装性检查通过
- 真机：安卓 Chrome 安装、iPhone Safari 添加到主屏幕（需要你在手机上试，部署到 HTTPS 后）

## 6. 本阶段不做

离线开单 / 离线查看数据、消息推送通知（低库存、新付款提醒）、上架应用商店。
