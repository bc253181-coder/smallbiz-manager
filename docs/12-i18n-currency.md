# 12 · 多语言与店铺币种 · 设计

> 阶段 16。

## 1. 现状与问题

- **所有店铺的币种都是人民币**：数据库有 `tenants.currency` 字段，但开店和设置页都没有地方选，马来西亚的店铺金额也显示「¥」，套餐页也按人民币价格显示。这是**目前就存在的问题**，应该先解决。
- **界面只有中文**：前端约 107 个文件、1900 处中文文字；后端约 180 处错误提示也是中文。马来西亚的非华人员工、店里请的外籍员工看不懂。

## 2. 店铺币种

| # | 规则 | 说明 |
|---|---|---|
| C1 | **开店时选择币种** | 人民币 CNY（¥）、马币 MYR（RM）、新币 SGD（S$）、美元 USD（$）、港币 HKD（HK$）、新台币 TWD（NT$）、泰铢 THB（฿）；按选择的地区自动带出时区（例如选马币 → 吉隆坡时间） |
| C2 | **开店后能否改币种** | 还没有任何销售单、采购单、收款时可以改；有业务数据后不能改（改了会让历史金额的含义变掉），页面说明原因 |
| C3 | 显示 | 所有金额（页面、打印单据、对账单、Excel 导出表头）用店铺币种符号 |
| C4 | 套餐价格 | 仍只有人民币和马币两种价格：马币店铺看马币价格和 TNG / DuitNow 收款码，其他币种的店铺看人民币价格 |
| C5 | 已有店铺 | 全部保持人民币；时区是吉隆坡 / 新加坡的店铺**提示**店主确认币种（不自动改，避免改错） |

> **不做"一张单多种货币"**（按汇率换算、多币种报表）：小商户很少需要，而且会让报表、应收、成本都变复杂。如果确实有需要，放到以后单独做。

## 3. 多语言

| # | 规则 | 说明 |
|---|---|---|
| L1 | **语言** | 简体中文（现有）+ **English**。代码按可扩展方式组织，以后加马来语（Bahasa Melayu）只需要补一份翻译文件 |
| L2 | **按人设置** | 每个用户自己选界面语言（同一家店，老板用中文、员工用英文）；第一次打开按浏览器语言自动选择；登录页和右上角头像菜单都能切换 |
| L3 | 翻译范围 | 所有页面文字、按钮、提示、表单校验、错误提示、套餐页、用户协议 / 隐私政策（英文版）、打印的销售单和对账单、Excel 模板表头和导出表头、客服机器人的界面文字 |
| L4 | **不翻译的** | 商户自己录入的内容（商品名、客户名、备注）、客服话术库（平台管理员自己维护，可以按语言分别写，本阶段只做中文）、平台后台 |
| L5 | 后端错误提示 | 按错误代码翻译：接口返回 `code` + 当前语言的 `message`；没有翻译的代码回退到中文 |
| L6 | 日期和数字 | 中文：2026/11/09；英文：09 Nov 2026；千分位按语言显示 |
| L7 | 导入 | Excel 导入同时认中文表头和英文表头 |

## 4. 技术方案（实际实现，2026-11-09）

- 前端没有用 i18next，而是一个很小的 `tr()`：**代码里直接写中文原文，中文原文就是词典的键**。中文用户不需要词典；英文词典（约 1400 条，77KB）单独打包，只有英文界面才下载。切换语言刷新页面，所以模块顶层的文字（状态名称表等）也是正确语言
- 现有约 1700 处中文用一次性脚本 `frontend/scripts/i18n-codemod.mjs`（TypeScript 语法树）自动包进 `tr()`；`npm run build` 先跑 `scripts/i18n-check.mjs`：代码里有没包进 `tr()` 的中文、或英文词典缺词，构建就失败
- 同一个中文词在不同位置英文不同时用 `trc('语境', '原文')`
- **后端错误提示在前端翻译**（没有用 MessageSource）：先找逐字翻译，找不到用按错误代码的通用英文（`ERR:代码`，约 110 条），都没有显示中文原文
- 数据库里系统生成的中文（库存流水原因「销售 SO-…」、默认仓库「主仓库」、「未分类」）在显示时按固定格式翻译；英文用户开店时默认仓库直接叫 Main warehouse
- Excel / CSV：英文界面下载时带 `lang=en`，后端按 `resources/i18n/excel_en.tsv` 翻译表头、工作表名、状态文字、模板说明和文件名；导入同时认中文和英文表头、英文状态值
- 店铺币种：已有店铺之前没有地方选币种，所以**未确认过币种的老店铺即使已有业务数据，也可以修正一次**（只改显示符号，不换算金额）；时区在马来西亚 / 新加坡但仍是人民币的店铺，仪表盘提示店主确认

## 4.1 原设计中的技术方案

- 前端：`i18next` + `react-i18next`；翻译文件按模块拆分（`zh-CN/sales.json`、`en/sales.json`…），英文翻译文件随页面按需加载，不增加中文用户的首屏大小
- 一个检查脚本：扫描代码里还没提取到翻译文件的中文，构建时报错，防止以后新写的页面漏翻译
- 后端：Spring `MessageSource`（`messages_zh_CN.properties` / `messages_en.properties`），按用户语言（`users.locale`，没有登录时看请求头 `Accept-Language`）选择错误提示
- 数据库（Flyway V15）：`users.locale`

## 5. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/tenants` | 新增 `currency`（可选，默认人民币） |
| PUT | `/tenant` | 新增 `currency`；有业务数据时修改返回 409 `CURRENCY_LOCKED` |
| GET | `/tenant` | 新增 `currencyLocked`（是否已不能改币种） |
| PUT | `/auth/me` | 新增 `locale`（`zh-CN` / `en`） |

## 6. 测试计划

- 币种：开店选马币 → 金额显示 RM、时区为吉隆坡、套餐页显示马币价格；有销售单后改币种被拒；店员不能改
- 语言：用户切换英文后刷新仍是英文；同一家店两个人各自的语言互不影响；后端错误提示按语言返回；没有翻译的错误代码回退中文
- 检查脚本：代码里没有遗漏的中文（除允许的白名单，例如语言名称「中文」）
- 端到端：用英文界面完成"开店（马币）→ 建商品 → 开单 → 看报表"，金额全部是 RM；布局检查在英文下跑一遍（英文通常更长，容易撑破按钮和表格）

## 7. 本阶段不做

马来语和繁体中文翻译（结构支持，以后补翻译文件）、一张单多币种 / 汇率换算、客服话术多语言、平台后台英文版、从右到左的语言。
