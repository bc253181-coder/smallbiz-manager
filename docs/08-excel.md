# 08 · Excel 导入导出 · 设计

> 阶段 12。专业版权益里写的是"Excel 导出"（见 01 文档第 4 节）。

## 1. 要解决的问题

- **开店第一天最麻烦的是录商品**：几十上百个商品一个个填太慢。商户手上往往已有 Excel 表（进货单、旧系统导出）。
- **数据要能带走**：对账、给会计、做自己的分析，需要真正的 Excel 文件（数字是数字、日期是日期，能直接求和），而不只是 CSV。

## 2. 套餐划分（需要你确认）

| 功能 | 建议套餐 | 理由 |
|---|---|---|
| **导入**商品、客户、供应商 | **所有套餐**（免费版仍受 100 个商品上限；客户、供应商本来就需要标准版） | 降低上手门槛，新用户能马上把自己的商品放进来试用，更容易转为付费 |
| **Excel（.xlsx）导出** | **专业版** | 与已公布的专业版权益一致 |
| 现有 **CSV 导出**（报表、应收） | 标准版（不变） | 已经卖出的权益不收回 |

## 3. 导入规则

| # | 规则 | 说明 |
|---|---|---|
| I1 | **先下载模板** | 每种数据一个 .xlsx 模板：第 1 个工作表填数据（表头 + 1 行示例），第 2 个工作表是填写说明。也接受 .csv（UTF-8 / GBK 自动识别） |
| I2 | **先预检、再导入** | 上传后先逐行检查，不写数据库；页面显示"可导入 N 行、跳过 M 行、错误 K 行"，错误精确到"第 5 行 · 零售价：必须是数字" |
| I3 | **全部成功或全部不导入** | 只要有一行错误就不能导入，改好后重新上传；导入在一个事务里完成，不会出现导了一半的情况 |
| I4 | **重复数据** | 商品按 SKU（其次条码）判重，客户按电话（其次名称），供应商按名称。两种方式由用户选择：**只新增**（重复的跳过）或 **新增并更新**（重复的更新名称、价格、分类等资料） |
| I5 | **库存只在新增时设置** | 新商品的「初始库存」通过库存流水写入（与手工建商品一致，`stock_qty = 流水之和`）；**更新已有商品时不改库存**（库存只能通过入库/出库/盘点改变，保证可追溯） |
| I6 | 分类 | 按名称匹配，不存在则自动创建（一级分类） |
| I7 | 限制 | 文件 ≤ 5 MB、≤ 5000 行；免费版导入后商品总数不能超过 100；每店每分钟最多 10 次上传 |
| I8 | 安全 | 只读第一个工作表的单元格值，不执行公式、不解析宏；防压缩炸弹（限制解压比例和大小） |
| I9 | 权限 | 店主、管理员；店员不能导入 |

**商品模板列**：商品名称*、单位*、零售价*、进货成本*、SKU、条码、分类、批发价、库存预警值、初始库存、状态（在售/停售）、描述
**客户模板列**：客户名称*、电话、邮箱、地址、类型（个人/企业）、默认价格（零售/批发）、备注
**供应商模板列**：供应商名称*、联系人、电话、邮箱、地址、供应商品、备注

## 4. Excel 导出（专业版）

| 导出 | 内容 | 入口 |
|---|---|---|
| 商品 | 当前筛选结果：名称、SKU、条码、分类、单位、成本、零售价、批发价、库存、库存价值、状态 | 商品列表 |
| 客户 / 供应商 | 全部资料；客户另含累计消费、订单数、当前欠款（专业版） | 客户 / 供应商列表 |
| 销售 | 日期范围内的销售单（工作表 1：每单一行）+ 明细（工作表 2：每个商品一行，含成本和毛利） | 销售列表 |
| 采购 | 日期范围内的采购单 + 明细 | 采购列表 |
| 库存流水 | 日期范围内的每笔变动 | 库存流水 |
| 报表 | 现有 CSV 报表同时提供 .xlsx | 报表页 |

- 数字单元格存为数字（金额两位小数格式）、日期按**店铺时区**显示；表头加粗并冻结首行，列宽自适应
- 店员不能导出；导出内容不含成本时不受影响（店员本来就看不到成本）
- 单次最多 50,000 行，超过时提示缩小日期范围
- 文本以 `= + - @` 开头时加 `'` 前缀，防止公式注入（与现有 CSV 一致）

## 5. 技术方案

- 后端使用 **Apache POI**（读写 .xlsx）；导出用流式写入（SXSSF），大文件不占满内存
- 导入接口：`POST /imports/{products|customers|suppliers}?mode=CREATE_ONLY|UPSERT&dryRun=true|false`（multipart 文件）。预检和正式导入是同一套校验代码，正式导入前会再完整校验一遍（防止两次上传之间数据被别人改了）
- 模板：`GET /imports/{type}/template`
- 导出：`GET /exports/{products|customers|suppliers|sales|purchases|movements}?…筛选参数`；报表沿用 `/reports/*/export?format=xlsx`

## 6. 页面

| 页面 | 内容 |
|---|---|
| 商品 / 客户 / 供应商列表 | 「导入」按钮 → 导入弹窗；「导出 Excel」按钮（非专业版显示锁图标和升级说明） |
| 导入弹窗 | ① 下载模板 ② 选择文件 + 重复处理方式 ③ 预检结果（统计 + 错误列表，可下载错误报告）④ 确认导入 → 结果（新增 x、更新 y、跳过 z） |
| 销售 / 采购 / 库存流水 | 「导出 Excel」按当前日期范围 |
| 报表页 | 导出按钮可选 CSV / Excel |

## 7. 测试计划

- 用模板导入 3 个商品（含新分类、初始库存）→ 商品、分类、库存流水都正确，`stock_qty = 流水之和`
- 有一行错误时整批不导入，数据库没有任何变化；错误行号和字段准确
- 只新增：重复 SKU 跳过；新增并更新：价格被更新、库存不变
- 免费版导入超过 100 个商品被拒；店员导入 403
- CSV（UTF-8 带 BOM、GBK）都能正确识别中文
- 恶意文件：非 Excel 文件、超大文件、压缩炸弹、含公式单元格（只读缓存值或拒绝）
- 导出：用 POI 读回导出的文件，核对行数、数字类型、金额与数据库一致、日期按店铺时区；非专业版 403
- 店铺隔离：导入的数据只出现在当前店铺；导出不含其他店铺数据
- 端到端：下载模板 → 填 3 个商品上传 → 预检通过 → 导入 → 商品列表看到 3 个商品和库存 → 导出 Excel 并读回核对

## 8. 本阶段不做

导入销售单 / 采购单历史、导入时自动识别任意格式的表头（必须用模板列名）、定时自动导出到邮箱、Google Sheets 同步。
