# 07 · 员工邀请与权限管理 · 设计

> 阶段 11，专业版功能（按 01 文档第 4 节：专业版最多 5 个员工账号）。

## 1. 要解决的问题

店主需要让店员、合伙人用**自己的账号**登录同一家店：店员只开单、查库存，看不到成本和利润；店主能随时调整权限或移除员工，并知道每张单是谁开的。

## 2. 业务规则

| # | 规则 | 说明 |
|---|---|---|
| S1 | **角色沿用现有三种** | 店主 OWNER（每店 1 人）、管理员 ADMIN、店员 STAFF。权限矩阵不变（见 03 文档 B.13） |
| S2 | **邀请链接** | 店主生成邀请链接（选角色，可填备注如"小王"），通过微信发给员工。员工打开链接 → 登录或注册 → 确认加入。不发邮件，不需要知道员工邮箱 |
| S3 | 链接安全 | 随机令牌，数据库只存 SHA-256 摘要；**7 天有效、只能用一次**；店主可随时撤销；已是本店成员的人不能重复加入 |
| S4 | **人数上限** | 专业版：店主之外最多 **5 人**（已加入 + 未过期的待接受邀请都计入，避免发出去的链接超额）。免费版、标准版：只有店主 |
| S5 | 管理 | 只有店主能邀请、改角色、移除；不能移除或降级自己；员工可以自己"退出店铺" |
| S6 | **立即生效** | 被移除或改角色后，下一次请求就生效（不用等登录过期）：每个请求核对成员状态和角色，不一致返回 401，前端自动刷新令牌拿到新角色；已被移除的人回到"选择店铺" |
| S7 | **到期** | 专业版到期：员工数据和成员关系**都保留**，但员工暂时不能进入这家店（提示"店铺套餐已到期，请联系店主续费"）；店主不受影响。续费后员工自动恢复 |
| S8 | 留痕 | 销售单已记录开单人；销售列表新增「开单人」筛选（店主/管理员）；收款记录显示收款人 |

## 3. 数据库（Flyway V11）

**invitations**
| 字段 | 类型 | 说明 |
|---|---|---|
| id, tenant_id | | |
| token_hash | CHAR(64) UNIQUE | 链接令牌摘要 |
| role | VARCHAR(20) | ADMIN / STAFF |
| note | VARCHAR(50) | 备注（如员工名字） |
| status | VARCHAR(20) | PENDING / ACCEPTED / REVOKED（过期按 expires_at 判断） |
| expires_at | DATETIME(6) | 创建 + 7 天 |
| created_by, accepted_by, accepted_at | | |
| created_at, updated_at | | |

`tenant_members` 已有 role / status（ACTIVE / REMOVED），新增 `removed_at`、`removed_by`。被移除后再次受邀：复用原记录改回 ACTIVE（表上有 tenant_id + user_id 唯一约束）。

## 4. 接口

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| GET | `/members` | 成员列表（姓名、邮箱、角色、加入时间、最近登录）+ 待接受邀请 + 名额 used/max | 店主 |
| POST | `/invitations` | `{role, note?}` → 返回链接（只在创建时返回一次原文） | 店主 + 专业版 |
| POST | `/invitations/{id}/revoke` | 撤销 | 店主 |
| GET | `/invitations/preview?token=` | 链接对应的店铺名、角色、邀请人、是否有效（无需登录，限速） | 公开 |
| POST | `/invitations/accept` | `{token}` → 加入并切换到该店，返回新会话 | 已登录用户 |
| PUT | `/members/{id}/role` | `{role}` | 店主 |
| POST | `/members/{id}/remove` | 移除，同时作废对方在本店的刷新令牌 | 店主 |
| POST | `/members/leave` | 自己退出当前店铺（店主不可） | 成员 |

新增错误码：`INVITATION_INVALID`（不存在/过期/已用/已撤销，统一一个，不暴露原因细节）、`MEMBER_LIMIT_REACHED`、`ALREADY_MEMBER`、`CANNOT_MODIFY_OWNER`、`STORE_PLAN_EXPIRED`。

## 5. 页面

| 页面 | 内容 |
|---|---|
| **员工管理**（设置下新菜单，店主可见） | 名额"已用 2 / 5"；成员列表（角色下拉可改、移除）；待接受邀请（复制链接、撤销、剩余天数）；「邀请员工」弹窗：选角色 → 生成链接 → 一键复制，附角色权限说明 |
| **加入店铺** `/invite/:token` | 显示"XX 邀请你以店员身份加入「店铺名」"；未登录 → 登录 / 注册后回到此页；确认加入 → 进入店铺 |
| 店铺切换 / 账户 | 员工可"退出这家店铺" |
| 销售列表 | 开单人筛选、列表显示开单人（店主/管理员） |
| 员工被拦截时 | 专业版到期：选择店铺页该店显示"套餐已到期，请联系店主" |

## 6. 测试计划

- 邀请 → 接受 → 以店员身份登录：看不到成本、不能取消订单、不能访问供应商（403）
- 链接：过期、重复使用、撤销后都返回 INVITATION_INVALID；已是成员返回 ALREADY_MEMBER
- 名额：5 人 + 待接受邀请计入；第 6 个邀请被拒；撤销后释放名额；并发接受不超额（锁店铺行）
- 移除后**旧访问令牌立即失效**（不用等 2 小时）；改角色后立即生效
- 只有店主能管理；管理员、店员调用返回 403；不能移除店主
- 专业版到期：员工进店被拒、店主正常、成员关系保留；续费后恢复
- 标准版不能邀请
- 店铺隔离：A 店的邀请令牌、成员 id 在 B 店无效（404）
- 端到端：店主生成链接 → 新用户注册并加入 → 店员开单 → 店主在销售列表按开单人筛选看到这张单 → 移除 → 店员页面回到选择店铺

## 7. 本阶段不做

自定义权限（勾选每项权限）、多个店主 / 转让店铺、员工业绩提成报表、操作日志查询页面、邮件或短信邀请。
