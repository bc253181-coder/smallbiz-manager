# 15 · 在线支付 · 设计

> 框架和模拟支付已完成（2026-11-09），实现与测试记录见 04 文档阶段 19。接入真实渠道时：实现 `PaymentGateway` 接口（创建付款页、校验通知签名、查询订单），配置商户密钥，用渠道的测试环境跑一遍端到端流程。

> 阶段 19。正式收款需要你开通一个支付商户号（见第 6 节，需要你决定）。没有商户号也可以先开发：用「模拟支付」把整个流程做完、测完，拿到商户号后只需接上对应的支付渠道。

## 1. 要解决的问题

- 现在开通付费套餐只有两种方式：扫码付款后上传截图，等人工核对（最长 24 小时）；或者先在小红书买激活码再兑换。用户等待时间长、容易流失，你也要每天手动审核
- 用户多了以后，人工核对截图容易出错（金额不对、重复提交、截图造假）

## 2. 功能

| # | 功能 | 说明 |
|---|---|---|
| O1 | **在线支付，立即开通** | 「设置 → 套餐与续费」选择套餐和时长 → 点「在线支付」→ 跳转到支付页面付款 → 付款成功后自动回到本网站，**几秒内自动开通**，不需要上传截图、不需要人工审核 |
| O2 | **原有方式保留** | 扫码付款 + 上传截图、激活码兑换照常可用（在线支付暂时不可用时仍能开通） |
| O3 | **付款结果页** | 回到本网站后显示「正在确认付款…」→「已开通专业版，有效期至 …」；用户中途关掉页面也没关系，付款成功后照样开通，下次打开就能看到 |
| O4 | **付款记录** | 「付款记录」里显示在线支付的订单、金额、支付方式、时间；可以打印收据 |
| O5 | **平台后台** | 后台「付款」页显示在线支付订单（自动开通，不需要审核）；可按状态筛选；有异常（金额不符、付款晚于订单过期）单独列出，由你处理 |
| O6 | **自动对账** | 支付渠道的付款通知万一没收到，系统每 10 分钟向渠道查询一次未完成的订单，付了款的自动补开通 |

本阶段**不做自动续费**（不保存银行卡、不自动扣款）：到期前提醒用户续费即可，避免扣款纠纷和退款处理。

## 3. 开通规则（和现有方式完全一致）

- 金额、套餐、时长全部由服务端按价格表确定，下单时锁定；页面上的金额只用于显示
- 续费从当前到期日顺延；标准版升级专业版时剩余天数按现有规则折算
- 首月体验每个店铺只能用一次：下单时检查，开通时再检查一次（防止同时下两单）
- 只有店主可以付款；开通记录写入「套餐变更记录」，来源为「在线支付」

## 4. 安全（重要）

- **只认支付渠道服务器发来、并通过签名校验的付款通知**，不相信浏览器跳回来时带的任何参数（防止伪造「已付款」）
- 收到通知后再核对：订单存在、金额和币种与订单完全一致、订单属于这个店铺；不一致的不开通，记为异常
- **同一笔付款只开通一次**：渠道交易号唯一，重复通知、通知和对账同时到达都不会重复加天数
- 订单 30 分钟内有效；过期后才付款（极少见）不会丢钱：照样开通并标记，后台可见
- 商户密钥只放在服务器的 `deploy/.env`，不进代码库；用户的银行卡、支付密码只在支付渠道的页面输入，我们的网站接触不到
- 退款在支付渠道的商户后台操作，后台记录退款并可手动调整套餐（本阶段不做自动退款）

## 5. 技术方案

- 支付渠道做成可替换的接口：创建付款页、校验付款通知签名、查询订单状态。先实现「模拟支付」（只在开发和测试环境启用，正式环境无法开启），之后按你开通的渠道增加对应实现，可以同时启用多个（例如人民币用一个、马币用另一个）
- 复用现有付款单表：增加支付渠道、渠道交易号（唯一）、付款时间、异常原因等字段；新增「在线支付」开通来源
- 付款通知接口无需登录，但必须通过签名校验；所有通知原文记录 90 天，便于排查
- 对账任务每 10 分钟运行一次；后台显示最近一次对账时间
- 前端：套餐页增加「在线支付」按钮（有可用渠道时显示）；新增付款结果页（自动轮询订单状态）

## 6. 需要你决定：开通哪个支付渠道

所有渠道都需要你自己注册商户号（我不能代你注册），费率和资质要求以各官网当时的规定为准，注册前请自己确认：

| 渠道 | 适合 | 一般需要 |
|---|---|---|
| **微信支付 / 支付宝** | 人民币用户（小红书来的中国用户） | 中国大陆营业执照（个体户通常可以）、对公或法人银行账户；网站如在大陆服务器还需 ICP 备案 |
| **Stripe（马来西亚）** | 马币用户；也能收国际银行卡 | 马来西亚注册的公司或个体（SSM） |
| **Billplz / ToyyibPay 等本地渠道** | 马币用户，网银 FPX、电子钱包 | 以官网要求为准（一般比 Stripe 简单） |

我的建议：**先做「模拟支付」把流程全部完成**，同时你去申请你最容易开通的那一个；哪个先批下来就先接哪个。在那之前，人民币用户继续用扫码 + 截图 / 激活码。

另外提醒：首月体验只有 ¥1.99 / RM 1.00，很多渠道每笔有固定手续费，体验单可能几乎没有利润；可以考虑体验单仍走激活码，在线支付只用于正式套餐（开通渠道后再定）。

## 7. 测试计划

- 后端测试（用模拟支付）：下单金额来自价格表；签名错误的通知被拒绝；金额 / 币种不符不开通并记为异常；重复通知只开通一次；通知和对账同时到达只开通一次；过期后付款照样开通并标记；首月体验同时两单只开通一次；续费顺延和升级折算与现有方式一致；店铺隔离（不能查看别家订单）；非店主不能下单；正式环境无法启用模拟支付
- 端到端：选择套餐 → 在线支付 → 模拟支付页面「付款成功」→ 回到结果页自动显示已开通 → 套餐页和付款记录正确；模拟「付款失败 / 取消」→ 订单保持未付款，可以重新支付
- 接入真实渠道后：用渠道的测试环境（沙箱）跑一遍，再用真实小额付款验证一次（需要你操作）

## 8. 本阶段不做

自动续费 / 订阅扣款、自动退款、发票、在小红书店铺内直接支付。
