# 17 · 发码台 · 设计

> 高级永久会员只通过激活码开通，激活码在小红书销售。发码台让你在平台后台按小红书订单「取码 → 发给买家」，系统记录每个码的去向，同一个码不会发给两个人。

## 1. 要解决的问题

- 现在激活码只在生成时显示一次（系统只保存「指纹」），你要自己保存表格、自己记哪个码发给了谁，容易丢失、重复发、查不到
- 买家说「码不能用」或要退款时，查不到这个订单发的是哪个码、对方有没有兑换

## 2. 功能

| # | 功能 | 说明 |
|---|---|---|
| D1 | **取码发货** | 平台后台「发码台」：输入小红书订单号（必填）和数量（默认 1），点「取码」→ 系统给出还没发过的永久会员激活码，并标记为「已发出」。页面上有「复制」按钮，复制后发给买家 |
| D2 | **不会重复** | 同一个码只能被取一次；两个人同时取码也不会拿到同一个；同一个订单号再次取码时会提醒「这个订单已经发过 N 个码」，确认后才再发 |
| D3 | **查询** | 按订单号或激活码后 4 位搜索；每个码显示状态：**未发出 / 已发出**（订单号、时间、操作人）**/ 已兑换**（兑换时间、兑换的店铺）**/ 已作废** |
| D4 | **补发 / 再看一次** | 买家说消息丢了：在订单记录上点「显示激活码」再复制一次（每次查看都会记录） |
| D5 | **退款作废** | 在订单记录上点「作废」：还没兑换的码立即作废、不能再用；已经兑换的提示你到「店铺」页取消该账号的永久会员 |
| D6 | **库存提醒** | 显示「还可发出 N 个」；少于 10 个时，发码台和后台概况页提示「激活码快发完了」，一键补充生成 |
| D7 | **生成** | 生成激活码时原码**加密保存**在系统里（不再只显示一次），也仍然可以下载表格 |

## 3. 安全

- 原码用 AES-256-GCM 加密后保存，密钥只放在服务器的 `deploy/.env`（`CODE_ENCRYPTION_KEY`），不进代码库；数据库被拿走也看不到原码
- 兑换时仍然只比对「指纹」，加密的原码只用于发码台
- 发码台只有平台管理员能用；取码、查看、作废都记录操作人和时间
- 没有配置密钥时：发码台显示「请先配置 CODE_ENCRYPTION_KEY」，生成激活码按现在的方式（只显示一次）
- 以前生成的激活码（只有指纹、没有原码）：仍然可以兑换和作废，但不能从发码台取出，列表中标为「旧码」

## 4. 技术方案

- 激活码表增加：加密的原码、发出时间、发出人、小红书订单号、备注；新增「发码记录」表（取码、查看、作废的操作日志）
- 取码时按生成时间从早到晚取「未使用、未发出、未作废、批次未过期、永久会员类型、有原码」的码，行锁 + `SKIP LOCKED`，并发取码不会重复
- 接口：取码、按订单号 / 后 4 位搜索、显示原码、按订单作废、库存数量
- 前端：平台后台新增「发码台」页（取码框、刚取出的码和复制按钮、搜索、列表）；概况页显示库存提醒

## 5. 测试计划

- 取码：给出未发过的码并标记已发出；10 个请求同时取码，没有重复、数量正确；库存不足时提示还剩几个、不发出任何码
- 同一订单再次取码需要确认；按订单号、后 4 位搜索；状态随兑换、作废变化
- 显示原码与兑换一致（取出的码能兑换成功）；作废后兑换提示已作废；已兑换的码不能作废
- 加密：数据库里看不到原码；密钥不对时无法解密（报错而不是给出错误的码）；没有密钥时发码台不可用、兑换不受影响
- 只有平台管理员能访问；每次取码 / 查看 / 作废都有记录
- 端到端：生成一批 → 按订单取码 → 复制 → 用这个码在会员页兑换成功 → 发码台显示「已兑换」和店铺名

## 6. 本阶段不做

和小红书后台自动对接（自动读取订单、自动发货）；按订单自动核对是否已付款（以小红书后台为准）。
