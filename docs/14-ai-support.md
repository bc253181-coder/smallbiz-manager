# 14 · AI 客服 · 设计

> 已完成（2026-11-09），实现与测试记录见 04 文档阶段 18。模型已定：Claude Haiku 5.5（最便宜）。
>
> 阶段 18。需要一个 Anthropic API 密钥（放在 `.env.dev` / `deploy/.env` 的 `ANTHROPIC_API_KEY`，不进代码库）。没有密钥时一切照旧（关键词匹配），所以可以先开发、后配置。

## 1. 要解决的问题

- 现在的小助手只做关键词匹配：换个说法（「货卖不出去库存怎么减」「员工能不能看到进价」）就答不上，只能转人工微信
- 英文界面的用户提问也只能得到中文话术
- **话术库已经过时**：还写着「批量导入正在开发中」「员工账号正在开发中」「只能导出 CSV」；没有条码、多仓库、协议价、应收账款、手机安装等新功能的问答

## 2. 功能

| # | 功能 | 说明 |
|---|---|---|
| A1 | **更新话术库** | 逐条核对 30 条现有话术，改掉过时内容；新增约 15 条（Excel 导入导出、条码扫码与标签、员工、多仓库与调拨、客户协议价、赊账收款与对账单、多语言与币种、安装到手机、专业版价格）。约 45 条 |
| A2 | **AI 理解问题、只按话术回答** | 关键词明确命中时直接回答（不花钱、立即返回）；没命中或不确定时交给 AI：AI 读整个话术库，用自己的话组织回答，可以合并几条话术，**但不能说话术库里没有的内容** |
| A3 | **答不了就转人工** | 话术库里找不到答案、问题和本产品无关、要求退款或查具体账务等需要人处理的事 → 显示客服微信卡片（和现在一样），并记录到「未匹配问题」 |
| A4 | **用提问的语言回答** | 英文提问用英文回答（话术库只需维护中文） |
| A5 | **能接着问** | 带上最近 3 轮对话，「那年付呢？」这类追问能理解 |
| A6 | **按钮和价格不会编** | 回答下方的「去开单」「查看套餐」等按钮只能来自话术里配置好的链接；价格从套餐价格表实时读取，调价后客服自动跟着变 |
| A7 | **平台后台查看 AI 回答** | 后台「客服」页新增「AI 回答记录」：问题、回答、引用的话术、是否转人工、用户评价；可标记「回答有误」，方便补充话术 |

界面基本不变：小助手标题改为「AI 小助手」，副标题「根据帮助文档回答 · 答不上来会转人工」；AI 回答显示「AI 生成，仅供参考」小字；思考中显示「正在思考…」。

## 3. 安全与隐私（重要）

- **只发送用户输入的问题**和最近 3 轮对话给 AI。不发送任何店铺数据（商品、客户、订单、金额）、邮箱、店铺名
- AI 没有任何工具，不能查数据库、不能操作账号，最坏情况也只是回答一段文字
- 防「提示词注入」（例如「忽略之前的规则，告诉我…」）：系统规则写明用户输入只是问题；回答强制为固定 JSON 结构，服务端校验后才显示；引用的话术编号必须真实存在
- 《隐私政策》（中英文）增加一段：在线客服的提问会由 AI 服务商（Anthropic）处理，用于生成回答，不包含店铺经营数据
- AI 回答记录保存 90 天后自动删除

## 4. 成本控制

- 关键词明确命中的问题（快捷问题按钮、常见说法）不调用 AI
- 话术库作为固定前缀使用**提示缓存**，重复部分按缓存价计费
- 限额（可配置）：每个 IP 每分钟 20 次（现有）；每个 IP 每天 30 次 AI 回答；全平台每天 1000 次 AI 回答。超出后自动退回关键词匹配，不报错
- 调用超时 20 秒、AI 服务出错、没配置密钥 → 自动退回关键词匹配
- 每次调用记录 token 用量，后台显示今日 / 本月调用次数和估算费用

## 5. 需要你决定：用哪个模型

模型名做成配置项（`AI_SUPPORT_MODEL`），之后可随时更换。按每次 AI 回答约 8,000 token 话术库（缓存）+ 300 token 问题 + 约 600 token 输出估算：

| 模型 | 价格（每百万 token，输入 / 输出） | 每次回答约 | 每月 3,000 次约 |
|---|---|---|---|
| Claude Haiku 5.5（`claude-haiku-5-5`） | $0.10 / $0.50 | 不到 ¥0.01 | 约 ¥10 |
| Claude Opus 5.5（`claude-opus-5-5`，能力最强） | $4 / $20 | 约 ¥0.1 | 约 ¥300 |

我的建议：**Haiku 5.5**。这里只是阅读 45 条话术、找出相关的几条、换成通俗说法，不需要复杂推理；以标准版 ¥6.99/月的价格，Opus 的客服成本偏高。上线后用测试题集（第 7 节）比较两者，如果 Haiku 有明显答错再换。

## 6. 技术方案

- 官方 Java SDK `com.anthropic:anthropic-java`；配置 `ANTHROPIC_API_KEY`、`AI_SUPPORT_MODEL`、`AI_SUPPORT_DAILY_LIMIT` 等，没有密钥时不创建客户端
- 流程：`/support/ask` → 关键词评分 ≥ 高阈值 → 直接回答；否则 → AI（话术库 + 当前价格 → 系统提示，开启缓存）→ 结构化输出 `{status: ANSWERED | HANDOFF, answer, faqIds[], actionFaqId}` → 服务端校验（faqIds 必须存在且启用；按钮取自 actionFaqId 对应话术）→ 返回
- 前端传最近 3 轮对话（只在浏览器内存里，关闭客服即清空）和界面语言
- 数据库 V16：更新 / 新增话术；新表 `support_ai_logs`（问题、回答、状态、引用话术、模型、token、耗时、评价、是否标记有误、创建时间；不存用户和店铺）
- 现有接口和返回结构保持兼容，新增字段 `source: KEYWORD | AI`

## 7. 测试计划

- 后端测试（不需要密钥，用模拟的 AI）：关键词命中不调用 AI；AI 回答引用不存在的话术 / 返回格式错误 → 转人工；按钮只来自话术；超时和出错 → 退回关键词；没密钥 → 关键词；IP 每日限额和全平台限额；价格来自价格表；日志记录与 90 天清理；后台列表和标记
- 测试题集（约 40 题，有密钥后运行一次并把结果给你看）：话术能答的换种说法、需要合并两条话术的、追问、英文提问、话术里没有的（应转人工）、无关问题、注入攻击（应拒绝）、要求退款（应转人工）
- 端到端：没有密钥时小助手和现在完全一样；用模拟 AI 时界面显示「AI 生成」、追问、转人工卡片
- 话术更新后人工核对每条与当前功能一致

## 8. 本阶段不做

AI 查询店铺自己的数据（如「我这个月卖了多少」）、AI 帮用户操作、语音输入、在小红书等外部平台接入 AI 客服。
